MANDATORY WORKSHOP POLICY — ALL CLIENTS (App, CLI and VS Code)
Use exact mode="autopilot" on every request except init and promote:
readiness, product, implementation, read-only resumption and future requests.
App/CLI retain /agent/list selection and prepend this line plus a blank line
to the original non-lifecycle request (no slash wrapper):
  mode="autopilot"

  <complete request text>
App/CLI init/promote messages remain unchanged, without mode. VS Code uses
the commands above, omitting mode only on init/promote. Shell installation
commands remain unchanged. There is no optional workshop mode selector.
Autopilot does not enlarge the request scope: readiness/resumption remain
read-only, and requested stops, plan approvals, impactful-action approvals
and final outcome validation remain required. Untargeted
federation autopilot can span the meta-selected sub-squads. A real registered
squad target narrows routing; the guide never invents that name.
Optional reference: request; federation squad; init profile; single-squad
pack; discovery quick|standard|deep|skip where applicable; tier fast|default;
owner as an existing roster member. These hints are omitted by default.
No mode=interactive, mode=init, mode=promote or cost-ceiling is supported here.
Mandatory autopilot does not unlock self-report Copy gates or grant approval.
The guide has been browser-simulated, not dispatched in an actual VS Code
host. Verify installed prompt discovery and real behavior separately.
